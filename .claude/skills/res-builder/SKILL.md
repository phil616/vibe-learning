# RES Builder

将 `material/` 中的原始学习材料提炼为规范的 `.res.md` 单文件或 `.res/` 资源目录。

**两个目录的职责边界：**

| 目录 | 角色 | 读/写 |
|------|------|-------|
| `material/` | 原料仓（暂存区）— 用户投放的杂乱原始资料 | **只读**，res-builder 从此处读取内容 |
| `workspace/<项目>/` | 知识库 + 路线图 — 结构化输出 | **只写**，res 文件必须写到这里 |

> ⛔ **严禁将任何 res 文件写入 `material/` 目录。**
> `material/` 是输入源，处理完成后其中的原始文件可直接删除，它不存储任何生成物。

## 第零步：读取 material/ 并锁定输出路径

> ⚠️ **路径锁定规则（最重要）**
> 项目目录名必须从文件系统的实际目录列表中读取，**严禁**从对话历史或上下文记忆中推断或拼写项目名。
> 写入任何文件前，必须先验证目标目录物理存在，不存在则停止并报错。

### 1. 扫描 material/ 目录

列出 `material/` 下所有文件（忽略 `.gitkeep`），让用户确认要处理哪些：

```
在 material/ 下发现以下原始资料：
  [1] Go语言入门教程.txt
  [2] goroutine详解.md
  [3] go-channel笔记.txt

请问要处理哪些文件？（输入编号，多个用逗号分隔，或输入"全部"）
```

若 `material/` 为空（只有 `.gitkeep`），提示用户先把资料放进去：
```
material/ 目录目前为空。请先将原始资料（文本文件、复制粘贴的内容等）放入 material/，
然后再次触发本 skill。
```

### 2. 从文件系统读取并锁定目标项目

**执行以下操作，列出 workspace/ 下所有现有目录：**

```bash
ls workspace/
# 或 Windows: dir workspace/
```

将实际读取到的目录名完整列出，让用户按编号选择：

```
workspace/ 下现有以下学习项目（直接从文件系统读取）：
  [1] go-learning
  [2] network-learning
  [3] 新建项目（输入项目名）

请选择编号：
```

- 用户选择已有项目编号 → **直接使用列表中显示的目录名**（原样复制，不做任何改写）
- 用户选择新建 → 输入项目名后，**立即创建目录** `workspace/<输入名>/`，然后用 `ls workspace/` 确认创建成功，以文件系统返回的实际目录名为准

### 3. 写文件前的强制验证

在生成任何 res 文件之前，执行路径验证：

```bash
ls workspace/<锁定的项目名>/
```

- 若目录**存在** → 继续，输出路径锁定为 `workspace/<锁定的项目名>/`
- 若目录**不存在** → **立即停止**，输出错误：
  ```
  ❌ 目标目录 workspace/<项目名>/ 不存在，停止写入。
  请检查项目名是否正确，或先执行 workspace-init 创建该项目。
  ```

### 4. 若在学习项目目录内直接调用

若当前目录已存在 `AGENTS.md` 或 `*.rdp.md`，则以**当前目录的实际路径**为输出路径，
通过 `pwd`（Linux/macOS）或 `cd`（Windows）命令读取，不依赖对话上下文。

## 第一步：判断输出形态

> 📌 **路径已锁定：** 所有文件写入 `workspace/<第零步确认的精确目录名>/`，绝不写入 `material/`。
> 如果不确定当前锁定的目录名，重新执行第零步第 2 节的 `ls workspace/` 命令确认。

根据输入材料的体量决定输出格式：

| 条件 | 输出格式 |
|------|---------|
| 整理后预计 < 600 行 | 单文件：`科目名.res.md` |
| 整理后预计 ≥ 600 行，或明显可分为多个独立主题 | 目录：`科目名.res/` |
| 用户明确指定格式 | 遵从用户指定 |

判断后告知用户："这份材料整理后约 X 行，我将生成 [单文件/目录] 格式。"

## 单文件格式：`workspace/<项目名>/科目名.res.md`

> 完整写入路径示例：`workspace/go-learning/Go语言.res.md`

### 文件头

```markdown
---
subject: Python 语言学习
type: res
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - 《Python编程：从入门到实践》第3版
  - https://docs.python.org/3/
  - 用户笔记（2025-03-18）
---

# Python 语言学习·资源库

> 本文件由 res-builder 自动整理，供 rdp-builder 生成学习路线图使用。
> 原始来源见头部 sources 字段。
```

### 内容结构规范

每个知识块用二级标题分隔，格式固定：

```markdown
## [编号]. [知识块名称]

> 来源：[具体来源，如书名章节、URL、或"用户笔记"]

[整理后的内容正文]

### 核心要点
- 要点一
- 要点二

### 关键术语
| 术语 | 解释 |
|------|------|
| GIL  | Global Interpreter Lock，全局解释器锁 |

### 代码示例
```python
# 示例代码
```

### 扩展阅读
- [可选] 相关链接或书目
```

**整理原则：**
- 保留原始知识内容，不删减核心信息
- 修正格式错误、统一排版
- 提取隐含的"核心要点"和"关键术语"，原文没有也要补充
- 代码块加语言标识
- 来源必须标注，方便追溯

## 目录格式：`workspace/<项目名>/科目名.res/`

> 完整写入路径示例：`workspace/go-learning/Go语言.res/`

### 目录结构

```
workspace/<项目名>/Python学习.res/
├── index.md              ← 总目录，列出所有文件及其内容摘要
├── 01-语言介绍.md
├── 02-基础语法.md
├── 03-函数与作用域.md
├── 04-面向对象.md
└── ...
```

### `index.md` 格式

```markdown
---
subject: Python 语言学习
type: res-index
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - [来源列表]
---

# Python 语言学习·资源目录

| 文件 | 覆盖内容 | 来源 | 行数 |
|------|---------|------|------|
| [01-语言介绍.md](./01-语言介绍.md) | Python历史、设计哲学、适用场景 | 《Python编程》第1章 | ~120 |
| [02-基础语法.md](./02-基础语法.md) | 数据类型、控制流、列表推导 | 《Python编程》第2-5章 | ~280 |
```

### 各章节文件格式

与单文件中的"知识块"格式相同，但每个文件只包含一个主题：

```markdown
---
subject: Python 语言学习
chapter: 02-基础语法
type: res-chapter
---

# 基础语法

> 来源：《Python编程：从入门到实践》第2-5章

[内容...]
```

文件命名规则：`NN-简短主题名.md`（NN 为两位数字序号，从 01 开始）

## 内容整理质量标准

### 必须做的

- **保真**：不曲解原始材料的意思，有疑问的地方用 `> [注]` 标注
- **补全**：原文语焉不详的地方，基于领域知识补充，并标注 `[补充]`
- **去噪**：删除重复内容、无关的页眉页脚、广告性文字
- **统一**：代码风格、术语拼写在文件内保持一致
- **标源**：每个知识块的来源必须在 `> 来源：` 行中注明

### 不应该做的

- 不得改写核心知识判断（如"Python 是解释型语言"不能改成"编译型"）
- 不得将推测性内容与事实混写，未确认的内容需加 `[待确认]`
- 不得压缩代码示例（代码要保持完整可运行）
- 不得生成 COVERAGE / STATUS / LOGS（这是 rdp-builder 的职责）

## 特殊输入处理

### 输入是 PDF 或图片
提示用户将文字内容复制后保存为 `.txt` 文件放入 `material/`。
如果工具支持读取 PDF 文本，直接提取后按上述流程处理，并在 `> 来源：` 中注明文件名。

### 输入是网页 URL
使用 web_fetch 获取页面内容，提取正文（去除导航、页脚等），再整理。
在 `> 来源：` 中记录完整 URL 和访问日期。
建议：将 URL 或已抓取的文本先保存到 `material/` 留档，再整理为 res。

### 输入是视频字幕 / 口语笔记
将字幕文件或笔记放入 `material/` 后处理：
- 整理语序，去除口头禅（"那个"、"就是说"）
- 保留知识点，删除与内容无关的互动话语
- 在来源处注明"字幕整理"或"口述笔记"

### 用户直接粘贴内容（未放入 material/）
接受内容并整理，整理完成后提示：
```
已完成整理。原始内容未经 material/ 暂存——如需留档，可将原始文本保存到 material/ 中。
```

### 输入混合多种来源
在 index.md 或文件头的 sources 中列出所有来源，
并在每个知识块的 `> 来源：` 行中精确标注具体来源。

## 完成后的提示

生成完成后，**用实际路径**（非占位符）输出提示语，例如：

```
已生成：workspace/network-learning/计算机网络.res.md
共 6 个知识块
总行数约：480 行

下一步：对 AI 说「帮我生成路线图」
→ rdp-builder 将读取 workspace/network-learning/计算机网络.res.md 并在同目录生成路线图
```

> ⚠️ 提示语中的路径必须是实际写入路径（从文件系统验证），不得使用 `<项目名>` 等占位符。

详细格式示例见 `references/res-examples.md`
