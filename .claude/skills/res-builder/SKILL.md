# RES Builder

将原始学习材料整理为规范的 `.res.md` 单文件或 `.res/` 资源目录。

## 第一步：判断输出形态

根据输入材料的体量决定输出格式：

| 条件 | 输出格式 |
|------|---------|
| 整理后预计 < 600 行 | 单文件：`科目名.res.md` |
| 整理后预计 ≥ 600 行，或明显可分为多个独立主题 | 目录：`科目名.res/` |
| 用户明确指定格式 | 遵从用户指定 |

判断后告知用户："这份材料整理后约 X 行，我将生成 [单文件/目录] 格式。"

---

## 单文件格式：`科目名.res.md`

### 文件头

```markdown
---
subject: Python 语言学习
type: res
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - 《Python编程：从入门到实践》第3版
  - https://docs.python.org/3/
  - 用户笔记（2025-03-18）
---

# Python 语言学习·资源库

> 本文件由 res-builder 自动整理，供 rdp-builder 生成学习路线图使用。
> 原始来源见头部 sources 字段。
```

### 内容结构规范

每个知识块用二级标题分隔，格式固定：

```markdown
## [编号]. [知识块名称]

> 来源：[具体来源，如书名章节、URL、或"用户笔记"]

[整理后的内容正文]

### 核心要点
- 要点一
- 要点二

### 关键术语
| 术语 | 解释 |
|------|------|
| GIL  | Global Interpreter Lock，全局解释器锁 |

### 代码示例
```python
# 示例代码
```

### 扩展阅读
- [可选] 相关链接或书目
```

**整理原则：**
- 保留原始知识内容，不删减核心信息
- 修正格式错误、统一排版
- 提取隐含的"核心要点"和"关键术语"，原文没有也要补充
- 代码块加语言标识
- 来源必须标注，方便追溯

## 目录格式：`科目名.res/`

### 目录结构

```
Python学习.res/
├── index.md              ← 总目录，列出所有文件及其内容摘要
├── 01-语言介绍.md
├── 02-基础语法.md
├── 03-函数与作用域.md
├── 04-面向对象.md
└── ...
```

### `index.md` 格式

```markdown
---
subject: Python 语言学习
type: res-index
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - [来源列表]
---

# Python 语言学习·资源目录

| 文件 | 覆盖内容 | 来源 | 行数 |
|------|---------|------|------|
| [01-语言介绍.md](./01-语言介绍.md) | Python历史、设计哲学、适用场景 | 《Python编程》第1章 | ~120 |
| [02-基础语法.md](./02-基础语法.md) | 数据类型、控制流、列表推导 | 《Python编程》第2-5章 | ~280 |
```

### 各章节文件格式

与单文件中的"知识块"格式相同，但每个文件只包含一个主题：

```markdown
---
subject: Python 语言学习
chapter: 02-基础语法
type: res-chapter
---

# 基础语法

> 来源：《Python编程：从入门到实践》第2-5章

[内容...]
```

文件命名规则：`NN-简短主题名.md`（NN 为两位数字序号，从 01 开始）

## 内容整理质量标准

### 必须做的

- **保真**：不曲解原始材料的意思，有疑问的地方用 `> [注]` 标注
- **补全**：原文语焉不详的地方，基于领域知识补充，并标注 `[补充]`
- **去噪**：删除重复内容、无关的页眉页脚、广告性文字
- **统一**：代码风格、术语拼写在文件内保持一致
- **标源**：每个知识块的来源必须在 `> 来源：` 行中注明

### 不应该做的

- 不得改写核心知识判断（如"Python 是解释型语言"不能改成"编译型"）
- 不得将推测性内容与事实混写，未确认的内容需加 `[待确认]`
- 不得压缩代码示例（代码要保持完整可运行）
- 不得生成 COVERAGE / STATUS / LOGS（这是 rdp-builder 的职责）

## 特殊输入处理

### 输入是 PDF 或图片
提示用户将文字内容粘贴进来，或说明无法直接读取二进制文件。
如果工具支持读取 PDF 文本，直接提取后按上述流程处理。

### 输入是网页 URL
使用 web_fetch 获取页面内容，提取正文（去除导航、页脚等），再整理。
在 `> 来源：` 中记录完整 URL 和访问日期。

### 输入是视频字幕 / 口语笔记
口语化内容需要书面化处理：
- 整理语序，去除口头禅（"那个"、"就是说"）
- 保留知识点，删除与内容无关的互动话语
- 在来源处注明"字幕整理"或"口述笔记"

### 输入混合多种来源
在 index.md 或文件头的 sources 中列出所有来源，
并在每个知识块的 `> 来源：` 行中精确标注具体来源。
